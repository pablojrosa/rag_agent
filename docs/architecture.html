02 · Runtime behavior

What happens when a user asks a question?

The online path is synchronous for the user. Telemetry is exported in the background and never replaces the application response.

⌨️1. BrowserPOST /chat with question, session and history
→
🛡️2. ValidateFlask checks JSON shape and required strings
→
🔎3. RetrieveEmbed question, query Pinecone, select passages
→
✨4. GenerateOpenAI answers using the retrieved context
→
💾5. CommitSave user and assistant messages in PostgreSQL
Response contract

The API returns response, message_id, and trace_id. The frontend renders the answer immediately and the trace ID lets an operator navigate from a UI interaction to the Langfuse trace.

03 · Knowledge design

The book RAG, end to end

Offline ingestion

The source PDF is split into passages. Each passage is transformed into an embedding and upserted to Pinecone together with metadata.

sourcepagechunk idtext

This process is represented by backend/src/services/vectorize_pdf.py. It builds the searchable knowledge base; it does not run on every chat request.

Online retrieval

The current question is embedded with the same OpenAI embedding model. Pinecone returns the closest chunks, which are formatted as context for the answer prompt.

question → embedding → Pinecone top_k=3 ↓ context = [source, page, id, text] ↓ OpenAI Responses → grounded answer
Why retrieve instead of sending the whole book? Retrieval reduces prompt size, focuses the model on relevant evidence, lowers cost, and creates an inspectable basis for groundedness evaluation.
What the similarity score means Pinecone's score ranks semantic proximity. It is useful for debugging retrieval quality, but it is not a truth probability and should not be presented as answer confidence.
04 · Quality loop

Tracing and evaluation are part of the runtime design

Trace

chat-request contains the request boundary. Nested observations capture rag-answer, embedding, retrieval, generation, and database save operations.

Scores

Langfuse evaluators calculate groundedness and relevance online. Offline experiments also calculate correctness against a reference answer.

Dashboard

Flask's monitoring adapter reads Langfuse observations, scores, metrics, and experiment runs. React renders the result without owning evaluation logic.

05 · Data boundaries

Which system owns which data?

PostgreSQL

System of record for chat messages and sessions. Flask commits the user message and assistant message as one transaction. Existing migrations remain for historical compatibility.

Langfuse

System of record for traces, observations, scores, datasets, evaluators, and experiment runs. It is also the source for the frontend evaluation dashboards.

Pinecone

System of record for book vectors and passage metadata. It is initialized lazily on first retrieval.

Browser

Owns the active chat presentation and sends the conversation history. The backend does not reconstruct the UI history from PostgreSQL before generating an answer.

06 · Design thinking

Decisions that shape the structure

Shared pipeline

Chat and offline experiments call answer_question(). This keeps production behavior and evaluation behavior aligned.

Best-effort telemetry

Missing Langfuse credentials or export failures do not break chat. Observability improves diagnosis without becoming a hard dependency for the user response.

Configuration-driven metrics

Metric names and evaluator definitions live in Langfuse. The dashboard can display new score definitions without adding a React column for every metric.

Provider separation

The application's OpenAI key generates answers. Langfuse's LLM connection powers judge evaluators. These are separate responsibilities and credentials.
